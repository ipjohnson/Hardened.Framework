Hardened.Framework · OpenAPI remediation plan

Making Seven Specs Build

Work required to generate operations and models from the seven published API descriptions in the evaluation. Eleven items, sequenced by what they unblock rather than by where they sit in the pipeline. Four of them account for every spec that currently fails.

base main @ 3bc8e5b branch feature/openapi-remediation clone ~/Hardened-openapi-work harness ~/testing/openapi-eval

Each fix reveals the next layer. Plan for re-measurement, not for a single pass.

Every blocker in the evaluation hid whatever sat behind it. Clearing GitHub's eight HOAT003 errors exposed 101,766 syntax errors that no one could see beforehand. The items below are grounded in what has actually been observed — but the list cannot be complete, because layers below the current blockers have never been reached.

The harness exists to answer that. run-all.sh rebuilds all seven specs in both modes and takes about three minutes. Run it after every item, and expect the plan to grow.

The work

Priority is p0 unblocks a spec, p1 correctness or policy that shapes the p0 work, p2 fidelity. Sizes are relative, not estimates.

W1p0 Guard [Required] on non-nullable value types

One call path is missing the check its sibling already applies. Unblocks Petstore on its own. Do this first — it is independent of everything else.
Where
Validation/ConstraintAttributes.cs:35 ForParameter — no guard Emitters/SchemaEmitter.cs:104 ForProperty — guard applied ForParameter(…) => Build(parameter, parameter.ConstrainedAsRequired, …) var emitRequired = property.ConstrainedAsRequired && !TypeMapper.IsNonNullableValueType(csType);

ForProperty takes required from its caller precisely so the caller can apply IsNonNullableValueType; the doc comment on the parameter says so. ForParameter computes it itself and skips the check, so a required integer path parameter gets [Required] on a long, and the validation generator emits value.itemId is null.

Note the build already emits VM0004 warning that this [Required] can never fail, then fails compiling the check it warned about. Both should go quiet together.

Done when Petstore builds clean with the validation generator enabled, and no VM0004 is emitted for spec-derived parameters.
W2p0 Name allocator: one component that owns every identifier

The largest item and the highest leverage. Closes 116,000 of the ~117,000 errors observed, across four specs.

Today NamingHelper.ToPascalCase is called at the point of use from six different places, splits on _ - space only, and lets every other character through unchecked. Point-of-use naming also cannot detect collisions, because a call site has no view of what else exists.

Shape
Runs over ServiceSpecModel after parse, before emit. 1. PROPOSE every nameable thing gets a candidate + provenance chain schemas · synthesized inline schemas · tags · operations properties · parameters · enum members · the spec file itself 2. RESOLVE group by (scope, candidate); singletons pass through; collisions walk out the provenance chain until separated 3. OVERRIDE sidecar map wins; an override that itself collides is a hard error 4. PUBLISH write the full name table into the .openapi-model.txt the task already emits

Name sources, in order. Read title first — it is OpenAPI's own naming affordance and it is everywhere: 4,700 in Stripe, 2,175 in GitHub, 741 in OpenAI, 37 of Slack's 48 definitions. .Title is currently read zero times anywhere in the build task. Fall back to synthesis only when it is absent.

Transliterate, do not delete. +1 and -1 must not both reduce to 1; StartTime< and StartTime> must not both reduce to StartTime. Replacement preserves what deletion destroys.

  • The table must be total over Unicode — real specs carry non-ASCII property names and emoji in enum values. Any character without a mapping needs a defined fallback.
  • - is context-dependent: a sign in -1, a separator in marketplace-purchase. Both appear in GitHub's document.

Scope, don't flatten. Properties need uniqueness within their type, enum members within their enum, types within their namespace. Flattening everything into one namespace is part of why Stripe produces 28 collisions.

Never disambiguate by arrival order. An ordinal suffix makes a name a function of iteration order, so reordering a spec renames unrelated types and silently breaks handler code. Qualify by content — parent scope, path position — so the name is a pure function of the thing's identity.

Determinism rules
sort before allocating Microsoft.OpenApi returns dictionaries; enumeration order is not contractual across versions ordinal everywhere StringComparer.Ordinal, ToUpperInvariant stable hashing reuse the FNV-1a in Validation/PatternRegistry.cs:77, which already avoids per-process GetHashCode randomisation
Done when Twilio, Slack and GitHub emit syntactically valid C#. Stripe's 28 HOAT005 are gone. A shuffle test — permute a spec's key order, regenerate — produces a byte-identical name table.
W3p0 URI space tree and namespaces

Gives W2 somewhere to put the disambiguation, so type names stay short and readable instead of growing to 84 characters.

Kiota's design overview names this problem directly: OpenAPI descriptions do not represent the URL hierarchy, so it must be constructed. Once names come from position in a tree they no longer need to be globally unique, because position already is.

The boundary trap
Namespaces alone do NOT fix the Stripe collision — the erased boundary just moves: A: POST /treasury/financial_accounts prop features.card_issuing → Treasury.FinancialAccounts .Features . CardIssuing B: POST /treasury/financial_accounts/features prop card_issuing → Treasury.FinancialAccounts.Features . CardIssuing identical Path-space and property-space need a marker between them. The operation works, and is information the reader wants anyway: A: Treasury.FinancialAccounts.Post.Features.CardIssuing B: Treasury.FinancialAccounts.Features.Post.CardIssuing distinct

Every leaf is then a short natural name, the hierarchy reads like the API, and the disambiguation lives entirely in structure a consumer can using away. It separates GET and POST on one path for free, which is needed regardless since their bodies differ.

Reserve namespace segments as taken names. Kiota's live issue is CS0118, “'X' is a namespace but is used like a type”, when a model name matches one of its own segments. Cheap to prevent in the allocator now, expensive to retrofit after a layout ships.

Done when Stripe's synthesized names are unique without ordinal suffixes, and no generated type name exceeds a reasonable length bound. No CS0118 across all seven specs.
W4p0 Carry type definitions, not strings

Types currently round-trip through a stringly-typed intermediate, which strips the namespace CSharpAuthor needs and hides a silent type-hijack bug.
The round trip
TypeMapper.MapPropertyToCSharpType → returns a string return $"List<{itemType}>"; // itemType's namespace: gone TypeMapper.GetTypeDefinition → parses it back out if (csType.StartsWith("List<")) { var inner = csType.Substring(5, csType.Length - 6); var innerType = GetTypeDefinition(ns, inner, false); // ns re-guessed

CSharpAuthor emits global::-qualified names out of the box when it holds a real ITypeDefinition. That is why the Pattern attribute comes out fully qualified — it is built with TypeDefinition.Get(...) directly — while ObjsBotProfile? does not.

The single ns parameter is the blocker for W3. It hard-codes the assumption that every model type lives in one namespace, and passes that same ns down for generic arguments. Survivable while everything is flat; the moment W3 lands it resolves types into the wrong namespace, and the failure is quiet.

Latent bug this also closes
GetPrimitiveTypeDefinition keys on the rendered name: "DateTime" => TypeDefinition.Get(typeof(DateTime)) "JsonElement" => TypeDefinition.Get("System.Text.Json", "JsonElement") A schema named date_time PascalCases to DateTime, hits that switch, and silently binds to System.DateTime instead of the generated model. No error. Same for json_element and byte.
Done when Every generated type reference is global::-qualified including generic arguments, and a spec declaring date_time generates and binds its own model.
W5p0 Never fail the build on a name; offer an override instead

Policy change, small code. Unblocks GitHub and Stripe, and encodes the principle that consumers do not control the specs they generate from.

HOAT003 refuses commit.commit, email.email, key.key, marketplace-purchase.marketplace_purchase and Stripe's error.error, advising the author to rename the schema or the property. That is sound for a spec you own and impossible for a vendor's published description.

The mechanism to resolve it automatically already exists: [JsonPropertyName] pins the wire contract everywhere else, so renaming the member costs nothing on the wire. The existing reasoning — that a member named differently from what the author wrote is worse to debug — holds when the author wrote it, and inverts when they did not.

Target policy
resolve automatically → warn, naming both the source and the chosen name author overrides → sidecar map, keyed by spec + JSON pointer hard error → only when genuinely impossible, or an override collides

Put overrides in a sidecar, not in the spec. x- extensions are wiped every time a vendor document is re-fetched. A sidecar file or MSBuild items survive re-fetching, which is the difference between a workflow and a chore. Precedent for the extension route already exists in the parser via x-filter-types; it is the wrong home for this.

While here, renumber the overloaded codes: HOAT003 and HOAT005 each mean two unrelated things today, one from the targets file and one from the build task, and both pairs are reachable in the same build.

Done when GitHub and Stripe generate without hand-editing their documents, each automatic rename is warned about, and a sidecar override changes a generated name.
W6p0 OpenAPI 3.1 via the Microsoft.OpenApi upgrade

Two specs, and the largest engineering lift. Insulated from W2–W5 by the IDL spine, so it can run in parallel.

Pinned at 1.6.22, which throws OpenApiUnsupportedSpecVersionException for 3.1.0. Confirmed with one document differing only in its version line. 3.1 support first landed in 2.0; the package is now at 3.10.0, so this is two majors, not a bump.

Breaking changes that hit this code
OpenApiSchema → IOpenApiSchema inline vs OpenApiSchemaReference OpenApiAny/OpenApiString removed → JsonNode (parser opens with `using Microsoft.OpenApi.Any;`) ParseNode infrastructure removed → visitor/writer APIs OpenApiReference reshaped → local vs external refs Semantics the library will not do for you: nullable: true → type: ["string", "null"] exclusiveMinimum → boolean in 3.0, number in 3.1

The parallelism is real and worth exploiting. The emitters run off ServiceSpecModel, not Microsoft's object model, so the parser swap is contained behind the IDL spine and the name allocator never sees IOpenApiSchema. The same upgrade also buys 3.2.

Done when OpenAI and Train Travel parse and generate. The 3.0 corpus produces byte-identical output to before the upgrade — that regression check is what makes the swap safe.
W7p1 Surface parse diagnostics; emit top-level array schemas

Two small independent fixes: one restores the reason behind every parse failure, one closes a dangling type reference.
Diagnostics — Parsing/OpenApiSpecParser.cs:17
var reader = new OpenApiStringReader(); document = reader.Read(text, out var diagnostic); // never inspected } catch (Exception) { return null; // message discarded }

diagnostic.Errors carries messages and JSON pointers, and the exception names the problem exactly. Both are dropped, so HOAT002 reports a bare “could not be parsed” on a 2.8 MB document. Reporting them costs nothing and would have made W6 self-evident.

Top-level arrays. Slack declares blocks as type: array; properties referencing it are typed Blocks? and no Blocks is ever declared, producing CS0246. Top-level scalar aliases in the same document resolve correctly, so this is specific to named array schemas.

Done when Every HOAT002 names a reason and a location, and Slack generates no unresolved type references.
W8p1 allOf: merge, collapse, relate

Four distinct shapes wearing one keyword. One of them is a build break; the rest lose information silently.
Observed distribution
allOf extension mixin ref-wrapper discriminators openai.yaml 156 145 4 5 107 github.yaml 54 10 26 4 5 train-travel.yaml 20 12 8 0 0 stripe · twilio · petstore — no allOf at all —
  • Merge properties by name. ParseAllOf appends every branch's properties without merging, so refining a constraint on an inherited property emits the member twice: CS0100 / CS0102. This is a build break and the only p0-shaped item in W8.
  • Collapse the ref-wrapper. allOf: [$ref X] plus a description is the standard OpenAPI 3.0 workaround for $ref ignoring siblings, and today it generates a duplicate record of X. It should alias and emit nothing. 3.1 makes the pattern obsolete, but every 3.0 document is full of it.
  • Ungate the relationship. ParsePolymorphism sets BaseRef only when an allOf branch is a $ref and declares a discriminator. But a discriminator says how to deserialize a hierarchy, not whether one exists. Train Travel is the proof: 20 compositions, zero discriminators, all flattened.
  • Mixins need interfaces. GitHub's 26 multi-$ref compositions have no expressible base class. Emitting an interface per composed schema and having records implement them handles mixins and extensions with one mechanism, and avoids threading base constructor arguments through positional records.

Interface caveat: if a base has count optional (int?) and a child marks it required (int), the record does not implement the interface — value-type nullability is not erased the way reference-type nullability is. Generate the interface from the merged view.

Done when The five-shape allOf probe builds, RefWrapper resolves to its target rather than a duplicate, and Train Travel's 20 compositions retain their relationships.
W9p1 oneOf / anyOf: a generated union type per site

Replaces the silent JsonElement fallback with a named type, typed accessors, and an emitted converter.

The discriminator is already parsed into DiscriminatorPropertyName and DiscriminatorMapping and then dropped at emission — the same shape as the allOf gate. Variant records are generated correctly today and simply never referenced.

Surface
public readonly record struct PetPayload { private PetPayload(object value) => Value = value; public object Value { get; } // pattern matching; handles scalar variants public bool TryGetCat(out Cat value); // discoverable, compile-time safe public bool TryGetDog(out Dog value); public static implicit operator PetPayload(Cat value) => new(value); public static implicit operator PetPayload(Dog value) => new(value); }
  • Get-only Value, construction through implicit operators. A validating setter moves to runtime a check the compiler makes for free.
  • No generic TryGet<T>. The variants are known at generation time, so named accessors are more discoverable and need no marker interface, leaving variant records unpolluted. Arity-free — 40 variants costs 40 methods and zero type parameters.
  • object, not a generated interface. An interface cannot represent scalar variants, and oneOf: [string, object] is pervasive — it is how Stripe models every expandable reference.
  • Beware the struct default. default(PetPayload) holds nothing and is silently constructible. Add HasValue, or use a sealed class so null carries absence honestly.
Emitted converter
write switch on runtime type, delegate to that variant's JsonTypeInfo read, disc. Utf8JsonReader is a ref struct — copy it, scan ahead for the discriminator, discard the copy, deserialize with the concrete JsonTypeInfo. Single pass, no DOM, order-independent. read, no disc. buffer to JsonElement, shape-match on required-property sets. Ambiguity is possible — warn at generation time, not at runtime. AOT call generated JsonTypeInfo<T> overloads, never JsonSerializer.Deserialize<T>. Register the union via JsonMetadataServices.CreateValueInfo<PetPayload>(options, converter).

Owning the converter avoids a live landmine. Using STJ's own polymorphism would put the discriminator in conflict with a declared property — and OpenAPI requires propertyName to name a real, required property. STJ throws on that conflict even when the property is [JsonIgnore], .NET 10 moved the throw earlier to serializer construction, and the discriminator property also cannot be required. A generated converter sidesteps all of it, and variant records keep their discriminator property as normal.

The union needs a name, and an inline oneOf at a property site has none. Take title, else derive from the property path through W2's allocator — do not concatenate variant names, which dies at 40 variants.

Done when A oneOf with a discriminator round-trips through a single-pass read, one without produces a warning naming the ambiguity, and no union reaches a handler as raw JsonElement without a diagnostic.
W10p2 Fidelity gaps that currently degrade silently

Each one is a place where the document says more than the generated signature does.
array of arrays → List<JsonElement> inner element type dropped multipart/form-data → JsonElement body form fields unmodelled format: binary → (nothing) no stream or file type format: uuid → string not Guid non-2xx responses → absent Problem generated, unreferenced by any signature

The governing rule is worth stating once and applying to all of them: always emit a compiling project; degrade to a weaker type rather than failing; say what degraded. Silent degradation is the actual defect here — it is easy to ship a handler taking JsonElement without ever learning what was lost.

Done when Every degradation emits a diagnostic naming the construct and the type it fell back to.
W11p2 PascalCase generated public members

Parameter interfaces carry the spec's casing onto public C# API surface.
public partial interface IGetItemParameters { [Required] long itemId { get; } // conventionally ItemId string? xTraceId { get; } }

Model records are already PascalCased with [JsonPropertyName] pinning the wire name, so the two halves of the generated surface follow different conventions today. This is a breaking change to generated API, so it belongs with W2 rather than after it — the allocator is where casing should be decided once for everything.

Done when No generated public member is camelCase, and wire names are unchanged.

Sequencing

Phase 1 — independent, start now
  W1  required-guard            one call site, unblocks Petstore
  W7  parse diagnostics         makes every later failure legible
  W6  Microsoft.OpenApi 3.x     longest lead time, parallel track behind the IDL spine

Phase 2 — the naming core, in order
  W4  type definitions          must precede W3, or namespaces resolve wrongly
  W2  name allocator            + W11 casing, decided once
  W3  URI tree and namespaces
  W5  never-fail policy         + sidecar overrides, + code renumbering

Phase 3 — fidelity
  W8  allOf                     merge is a build break; treat that part as phase 2
  W9  oneOf union types
  W10 remaining degradations

W4 before W3 is the one ordering that is not negotiable: introducing namespaces while types still travel as strings resolves generic arguments into the referencing type's namespace, and it fails quietly.

W6 has no dependency on the naming work in either direction, which is worth exploiting given it is the biggest single item. That independence is a property of the IDL spine, not an accident.

How to know it worked

  • The harness, after every item. ~/testing/openapi-eval/run-all.sh builds all seven specs in both modes in about three minutes and writes per-spec logs. The goal state is seven projects generating operations and models; compiling handlers is not required, since nobody is going to implement GitHub's 600 operations.
  • The shuffle test. Permute a spec's key order, regenerate, diff the name table. Byte-identical or the allocator is order-dependent.
  • The 3.0 regression check. Before W6, snapshot generated output for the 3.0 corpus. After the upgrade it must be byte-identical. This is the only thing that makes a two-major dependency swap safe to review.
  • The name table as a CI gate. Once it lands in the model file, a vendor spec update that renames a public type shows up as a reviewable diff instead of a compile error in a consumer's handler.
  • Re-measure the layers. Expect new findings each time a blocker clears. GitHub went from 8 errors to 101,766 the moment its first blocker was removed; nothing below Twilio's parameter-name failures has been seen at all.
